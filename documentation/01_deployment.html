Deployment guide: one always-on factory server

Target setup

Install both MySQL and the web application on one dedicated factory server. The server needs a stable network connection, a fixed/reserved local IP address, full-disk encryption, and automatic restart after a power interruption.

Employee browsers -- HTTPS --> Factory server
                                |- HTTPS reverse proxy
                                |- GNEM web application (Waitress, local only)
                                `- MySQL Community Server (local only)

Manager computer -- HTTPS --> Factory server
Power BI / future AI -- read-only MySQL connection --> Factory server

The employee web application, MySQL, and the factory server must remain running for immediate entry and saving. The manager computer does not need to remain on.

Before installation

  • [ ] Obtain a dedicated Windows computer approved by IT.
  • [ ] Reserve a fixed LAN IP address and the approved local DNS name slurry-management.local.
  • [ ] Enable BitLocker/full-disk encryption and automatic screen locking.
  • [ ] Install current Windows security updates and endpoint protection.
  • [ ] Install MySQL Community Server, Python, and an HTTPS reverse proxy approved by IT.
  • [ ] Create an encrypted backup destination separate from the server.
  • [ ] Do not use a personal Desktop, OneDrive folder, or shared drive as the live application or MySQL data location.

Copy the software

  • Copy the reviewed runtime release files to C:\SlurryManagement on the factory server. A versioned GitHub Release ZIP is recommended; Git itself is not required on the server.
  • Do not copy an existing .env file containing passwords. On the server, make a new .env by copying .env.example.
  • Open .env in a local text editor. It must not be committed to Git or copied to employee devices.

Example production settings:

ENVIRONMENT=production
DEPLOYMENT_MODE=single_server
SECRET_KEY=long-random-private-value
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=slurry_management
DB_USER=slurry_web_app
DB_PASSWORD=unique-private-password
WEB_HOST=127.0.0.1
WEB_PORT=5000
ALLOWED_HOSTS=localhost,127.0.0.1,172.23.19.139,slurry-management.local
BEHIND_TLS_PROXY=true
MANAGER_PIN=long-unique-manager-pin
LOW_YIELD_THRESHOLD=0.90

Replace the IP address with the factory server's actual reserved address. WEB_HOST=127.0.0.1 is intentional: only the local HTTPS gateway can contact the web app.

Create MySQL and least-privilege accounts

Log in to MySQL with an administrator account on the factory server. Replace the passwords below with long unique values.

CREATE DATABASE slurry_management CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

CREATE USER 'slurry_web_app'@'localhost' IDENTIFIED BY 'WEB_APP_PASSWORD';
GRANT SELECT, INSERT, UPDATE ON slurry_management.* TO 'slurry_web_app'@'localhost';
GRANT SELECT, INSERT, UPDATE ON system_import.* TO 'slurry_web_app'@'localhost';

CREATE USER 'slurry_powerbi'@'MANAGER_OR_GATEWAY_IP' IDENTIFIED BY 'POWERBI_READ_ONLY_PASSWORD';
GRANT SELECT ON system_import.* TO 'slurry_powerbi'@'MANAGER_OR_GATEWAY_IP';
FLUSH PRIVILEGES;

Use a temporary migration administrator account only for applying migrations. It needs database-definition rights while migrations run; do not use it to run the website.

Install and migrate

Open PowerShell as the dedicated application Windows account:

cd C:\SlurryManagement
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

Temporarily place the migration administrator credentials in .env, then run:

.venv\Scripts\python scripts\apply_migrations.py

After migration, restore DB_USER and DB_PASSWORD in .env to the restricted slurry_web_app@localhost account. Start a manual test:

.venv\Scripts\python main.py

Confirm locally that http://127.0.0.1:5000 responds. Do not make port 5000 publicly reachable.

HTTPS, certificate, and firewall

  • The deployed gateway is Caddy. Its configuration is deployment\caddy\Caddyfile; it listens on HTTPS 443 and forwards only to 127.0.0.1:5000.
  • Caddy creates an internal factory certificate for slurry-management.local. Read 09 HTTPS certificate setup before connecting another computer.
  • Windows Firewall rule GNEM HTTPS - Factory LAN permits inbound TCP 443 only on Private/Domain factory networks.
  • Do not allow employee computers to reach TCP 3306. Allow it only from the explicitly approved Power BI gateway/manager IP if remote Power BI direct-query is required.
  • Do not open port 5000 in Windows Firewall and do not port-forward 443 or 3306 from the internet router.

Start automatically

  • Configure MySQL as a Windows service with automatic startup.
  • Run the Python web application under a dedicated non-administrator Windows account as a Windows service or Scheduled Task triggered at startup.
  • Start both services with Start_GNEM_Slurry_Tracker.cmd. For manual recovery, use scripts\restart_factory_server.ps1; it starts the local web service and Caddy HTTPS gateway.
  • Configure Windows to restart automatically after a power failure where IT policy allows it; use a UPS.

Acceptance checklist

  • [ ] https://slurry-management.local works from an employee computer without a browser certificate warning.
  • [ ] Operator can submit a test production record and see it in Production records.
  • [ ] Operator can submit a test abnormality and update its open tracker owner/date.
  • [ ] Operator cannot open analysis or manager dashboard data.
  • [ ] Manager PIN opens the manager workspace and sign-out closes it.
  • [ ] Power BI read-only user can view system_import tables but cannot insert/update/delete.
  • [ ] MySQL cannot be reached from an employee workstation.
  • [ ] A backup completed and one restore test was recorded.
