v3.3 deployment and Slitting Power BI

Values to collect before starting

  • SERVER_IP: fixed LAN address of the GNEM/MySQL server.
  • POWERBI_IP: fixed LAN address of the approved new Slitting Power BI computer.
  • A new long random password for gnem_migrator.
  • A different long random password for slitting_powerbi.

Do not place real passwords in Git, this document, screenshots, or Power BI report files.

One-time permanent migrator repair

  1. On the factory server, open MySQL Workbench using a MySQL administrator account.
  2. Open deployment/sql/create_production_accounts.sql.template, copy only the four gnem_migrator grant statements and its CREATE USER statement into a temporary Workbench tab, replace MIGRATOR_LONG_RANDOM_PASSWORD, and run them. Do not save the completed SQL file.
  3. Add these private values to .env.departments on the server:
MIGRATION_DB_USER=gnem_migrator
MIGRATION_DB_PASSWORD=THE_NEW_MIGRATOR_PASSWORD
MIGRATION_CREATE_SCHEMAS=false

Keep the existing restricted DB_USER, DB_PASSWORD, SLITTING_DB_USER, and SLITTING_DB_PASSWORD unchanged. The website never receives migrator privileges.

Exact v3.3 deployment sequence

Run PowerShell on the factory server. Replace C:\GNEM\slurry-management-system if the installed folder differs.

Set-Location -LiteralPath 'C:\GNEM\slurry-management-system'
powershell -ExecutionPolicy Bypass -File .\scripts\backup_factory_database.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\stop_factory_server.ps1
git fetch --tags origin
git checkout v3.3.0
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\scripts\apply_migrations.py --status --department all
.\.venv\Scripts\python.exe .\scripts\apply_migrations.py --department all
.\.venv\Scripts\python.exe .\scripts\apply_migrations.py --status --department all
powershell -ExecutionPolicy Bypass -File .\scripts\start_factory_server.ps1

The first status check should list common migration 028_daily_task_shift_slots.sql for both departments and Slurry-only migration 029_attendance_login_timestamp_and_pin_lookup.sql. The final status must show pending=0 for both. If it does not, keep the application stopped and inspect the error; never mark a migration as applied manually.

Post-deployment verification

  • Open the Slurry and Slitting employee views and confirm each shows only its own department.
  • Open both TV URLs and check the fixed four-column layout, empty messages, charts, autoscroll, and ten-second bottom pause.
  • Create and edit a future task for each department, then confirm the correct production shift displays it.
  • Confirm attendance login and Excel export, including separate Saturday and Sunday columns.
  • Review logs/web-server.stderr.log and logs/display-server.stderr.log.

One-time Slitting Power BI account

  1. Give the new Power BI computer a fixed/reserved LAN address (POWERBI_IP).
  2. On the MySQL server, ensure MySQL listens on the server LAN interface, not only 127.0.0.1. Restart MySQL after changing bind-address.
  3. In an elevated PowerShell window on the server, restrict the firewall rule to the new computer:
New-NetFirewallRule -DisplayName 'GNEM MySQL - Slitting Power BI' -Direction Inbound -Protocol TCP -LocalPort 3306 -RemoteAddress POWERBI_IP -Action Allow
  1. In MySQL Workbench as administrator, run the slitting_powerbi statements from deployment/sql/create_production_accounts.sql.template after replacing the IP and password placeholders.
  2. Verify the account is read-only:
SHOW GRANTS FOR 'slitting_powerbi'@'POWERBI_IP';

The result should grant only SELECT on slitting_system_import.*.

Connect the new Power BI computer

  1. Install current Power BI Desktop and Oracle MySQL Connector/NET on the new computer.
  2. Run Test-NetConnection SERVER_IP -Port 3306. Continue only when TcpTestSucceeded is True.
  3. In Power BI Desktop, choose Get data → MySQL database.
  4. Server: SERVER_IP:3306. Database: slitting_system_import.
  5. Choose Database authentication and enter slitting_powerbi plus its private password.
  6. Select the required read-only tables. Start with production_records, abnormality_reports, daily_tasks, inventory_products, inventory_transactions, slitting_model_specs, and slitting_event_categories.
  7. Use Import mode unless a reviewed reporting requirement needs otherwise. Confirm refresh, dates, shifts, machines, models, and widths before publishing.

For Power BI Service scheduled refresh, install the standard-mode on-premises data gateway and Oracle MySQL Connector/NET on the gateway computer. Personal-mode gateway does not support this MySQL connector. Configure the gateway data source with the same server, database, and read-only credentials; never expose port 3306 to the internet.

Rollback

If application verification fails, stop the services and check out the previous tag. Do not reverse schema migrations by deleting columns. Restore the pre-deployment backup only when the database itself must be rolled back, and record that decision.
