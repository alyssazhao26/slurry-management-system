Security and privacy

Access model

RoleAccess
OperatorNo sign-in; submit operational forms, view normal records, and update approved fields on open tracker items
ManagerPIN-protected workspace; dashboards, rule-based exceptions, complete tracker, configurable fields
Web application accountLocal MySQL SELECT, INSERT, UPDATE only
Power BI/future AI accountRead-only SELECT only; separate account and password
Migration administratorTemporary database-definition permissions only while migrations are applied

No employee browser receives a MySQL password. Never share the manager PIN with employees.

Application protections currently implemented

  • Secure/HttpOnly/same-site manager session cookie in production.
  • Manager session expires after eight hours.
  • Manager PIN comparison avoids timing leaks and is throttled after repeated failures.
  • State-changing requests require a per-session anti-forgery token.
  • Production mode requires HTTPS proxy configuration, an explicit allowed-host list, a non-default secret key, and a non-default manager PIN.
  • Browser security headers reduce framing, unsafe content handling, and referrer exposure.
  • Record insertion uses database transactions and offline idempotency receipt IDs.

Required infrastructure protections

  • Place the server in restricted physical space. Employees should use their own computers, not the server console.
  • Enable BitLocker/full-disk encryption and automatic Windows lock.
  • Use a dedicated non-administrator Windows account for the application service.
  • Allow port 443 only from the factory network. Do not expose the service to the public internet.
  • Use https://slurry-management.local, never http://...:5000, from employee devices. The internal Caddy certificate must be trusted on each approved device; see HTTPS certificate setup.
  • Block MySQL port 3306 from employee devices. Permit it only for a fixed Power BI gateway/manager IP where needed.
  • Keep Windows, MySQL, Python dependencies, and endpoint protection current.
  • Keep .env, database backups, certificate keys, and MySQL passwords out of Git and shared folders.

Privacy principles

Collect only data needed for factory operations. Avoid personal details in free-text notes unless there is a documented business need. Do not store passwords, API keys, medical information, government IDs, or sensitive HR data in operational fields.

Define a retention period approved by management/IT. Restrict access to backups, Power BI workspaces, exports, and manager dashboards. Treat exports as operational data and keep them in an approved location.

AI guardrails

Any future external AI integration must be manager-only and server-side. The browser must never contain an API key. AI should receive the minimum necessary approved data, return structured summaries, and never autonomously edit records, close abnormalities, send external messages, or make safety decisions. Keep human approval, logging, prompt-injection resistance, and provider data-retention review in place before activation.

Future offline queue boundary

Browser offline queuing is not active in this release. If it is built later, it is approved only on dedicated factory devices with BitLocker/full-disk encryption, automatic locking, and restricted kiosk accounts. Each device must hold no more than 1,000 unsynced records for seven days, warn after 24 hours without successful sync, and delete a local record only after central SQL confirms receipt. It must never hold passwords, manager PINs, API keys, personal data, or attachments.
