Power BI and future AI integration

Power BI

Power BI should read the reporting schema through the dedicated slurry_powerbi account:

  • system_import.production_records
  • system_import.abnormality_reports

Use the factory server's internal hostname/IP and MySQL port 3306 only from the approved manager computer or on-premises data gateway. The account must have SELECT only. It must not use the web application's MySQL account.

For Power BI Service refresh, install the standard on-premises data gateway on an always-on approved computer and allow it to reach the factory server. Do not expose MySQL to the internet to make refresh work.

Power BI is a reporting reader. It should not write back to operational MySQL tables.

A weekly or monthly Power BI refresh is recommended for this factory setup and has negligible impact on GNEM. Keep refreshes scheduled outside peak reporting periods; do not allow many individual users to force simultaneous direct-query refreshes against the operational database.

AI: current status

The running application has rule-based exception analysis, not a connected LLM. It checks yield, plan variance, severity, downtime, and incomplete abnormality reports. These results are manager-only.

AI: safe future uses

  • Plain-language daily summaries of already-authorized records.
  • Trend detection across repeated abnormalities, machines, or shifts.
  • Draft investigation questions for manager review.
  • Explanations of dashboard changes with source record IDs.

AI: prohibited behaviour

  • Do not expose AI analysis to operators by default.
  • Do not send raw employee free text, secrets, or unnecessary personal data to an external provider.
  • Do not permit AI to edit records, close tracker items, change thresholds, or contact people automatically.
  • Do not put an AI API key in JavaScript, Power BI, a shared drive, or a browser.

AI deployment pattern

When approved, run AI as a manager-only server-side service with its own read-only SQL account. Retrieve only a bounded approved data set; validate structured output; log request metadata and human approval; and store generated summaries separately from source records. Review provider privacy, data retention, cost, and regional processing terms before use.
