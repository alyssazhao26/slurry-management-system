AI Cost Analysis Prompt Guide

This document replaces employee cost-failure checkboxes. Employees do not enter cost categories. A manager-only AI process may suggest them from operational records.

Data boundary

Give the model a read-only, selected record payload from system_import.production_records and system_import.abnormality_reports. Do not give it credentials, passwords, audit events, manager sessions, or unrestricted database access. The AI service should use a separate MySQL account with SELECT only, ideally through a restricted view or application query.

Cost-analysis input

For each event, send: event date/time, machine, process type, event type, severity/priority, resolved status, expected/actual finish, calculated duration, effective-time-cost flag, description, immediate action, solution, and relevant same-day production context (formula, planned, actual, qualified, achievement rate, qualified rate, notes).

Prompt template

You are a factory cost-impact analyst. Use only the supplied record data. Do not invent monetary values, root causes, or safety conclusions. Return JSON only:
{"suggested_cost_categories":["lost_production"],"confidence":0.0,"evidence":["short factual reason"],"data_gaps":["missing information"],"manager_questions":["question requiring confirmation"]}
Allowed categories: lost_production, scrap_rework, material_loss, maintenance_repair, energy_waste, labour_overtime, customer_delivery_impact, safety_environmental_impact.
A suggestion is advisory only; a manager must approve it before reporting.

Storage recommendation

Keep raw operational tables as the source of truth. Add a separate manager-only AI-results table later for prompt version, input record IDs, model, result JSON, confidence, approval decision, reviewer, and timestamps. Do not overwrite employee records with AI output.
