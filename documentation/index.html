GNEM Slurry Production Tracker documentation

This documentation describes the intended production design: one always-on factory server running the employee web application and MySQL locally. Employees use a browser link; they do not access MySQL. Managers use the same link for a PIN-protected workspace. Power BI and any future AI service use separate read-only database credentials.

Current capability statement

  • Operators do not sign in. They can submit forms, view recent operational records, and update limited fields on open tracker items.
  • The manager workspace is PIN-protected. It shows dashboards, rule-based exceptions, and form configuration.
  • Reporting tables are system_import.production_records and system_import.abnormality_reports.
  • Rule-based analysis is active. An external generative-AI API is not connected yet.
  • Records write directly to MySQL while the factory server is available. Browser offline queuing is not enabled yet.

Do not treat a development installation as production until the deployment and security checklists have been completed by the person responsible for factory IT.
